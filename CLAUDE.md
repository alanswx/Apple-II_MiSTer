# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is an Apple //e for [MiSTer](https://github.com/MiSTer-devel/Main_MiSTer/wiki),
targeting the DE10-nano (Cyclone V 5CSEBA6). Unlike the sibling Apple IIgs core,
**everything here is synthesizable RTL** — there is no ARM-side emulation. The HPS
provides file I/O, the OSD, and the RTC; the FPGA is the whole machine.

Lineage: Stephen Edwards' Columbia `apple2fpga` (DE2) → the MiST port at ws0.org →
this MiSTer port. Most of `rtl/*.vhd` still carries that ancestry, which is why the
core is VHDL with SystemVerilog bolted on at the edges (`Apple-II.sv`, `rtl/*.v`,
`rtl/floppy_track.sv`).

**This code runs on real hardware. Do not make changes to memory or clocks that
aren't FPGA friendly.** Specifically:

- **Use clock enables, never derived clocks.** The whole core runs on one 14.318 MHz
  `clk_sys`. `PHASE_ZERO`, `CLK_2M`, `Q3` and friends are *enables* gated off that
  clock, not separate clock domains — even where a signal is named like a clock.
  Do not write `always @(posedge PHASE_ZERO)`.
- **No inferred latches, no async resets** in new logic.
- **Watch block RAM.** The device has 553 M10K blocks and the core already uses
  399 (72%). See "Resource budget" below before adding any memory.
- If you add a real second clock domain, it needs proper CDC and an SDC constraint.

## Build

Standard MiSTer Quartus flow. Quartus 17.0.x is what this core is known to fit with.

```bash
quartus_sh --flow compile Apple-II          # full compile -> output_files/Apple-II.rbf
quartus_map Apple-II && quartus_fit Apple-II  # map+fit only, to check resources fast
```

`build_id.v` is generated by the MiSTer build scripts. If you are compiling by hand
and it is missing, create a stub — synthesis will fail without it.

Read the fit report before and after any memory change:

```bash
grep -E "ALMs|block memory|RAM Blocks" output_files/Apple-II.fit.summary
```

Release bitstreams go in `releases/` with a datestamped name, matching the existing
convention (`Apple-II_20260603.rbf`).

## Core Architecture

### Top level

| File | Role |
|------|------|
| `Apple-II.sv` | MiSTer wrapper: OSD/`CONF_STR`, HPS disk mounting, PLL, main + aux RAM arrays, audio out, HDD block plumbing |
| `rtl/apple2_top.vhd` | Machine assembly: instantiates CPU, video, disk, slots, and mixes audio |
| `rtl/apple2.vhd` | The Apple itself: address decode, soft switches, memory banking, RAM/video multiplexing |
| `rtl/timing_generator.vhd` | Sather's IIe HAL timing equations — the heart of the core |

### Clocks

One PLL (`rtl/pll/pll_0002.v`), two outputs:

- `outclk_1` = **14.318181 MHz** = `clk_sys`. Everything runs here.
- `outclk_0` = **57.272727 MHz** = `CLK_VIDEO` (4× clk_sys).

The ratio is exact, not approximated: 50 MHz × 63/220 = 315/22 MHz. Accuracy is
limited only by the board crystal. **There is nothing to gain by touching the PLL.**

### Timing model — read this before touching video or the CPU

`rtl/timing_generator.vhd` implements the Apple IIe HAL equations (Sather,
*Understanding the Apple IIe*). It is cycle-exact and has been verified in
simulation:

- NTSC frame = 262 lines × 912 `clk_sys` = 238,944 clocks; PAL = 312 × 912 = 284,544.
- Exactly **one stretched ("long") 16-clock PHI0 cycle per line**; every other cycle
  is 14 clocks. That gives the correct 17,030 cycles/frame NTSC, 20,280 PAL.
- VBL is asserted for 70 lines NTSC / 120 PAL, latched at RASRISE1.

Do not "simplify" this into a plain counter. The long cycle is what makes the
colorburst phase and every timing-sensitive title work.

### The RAM multiplexing constraint

This is the single most important structural fact in the core.

`rtl/apple2.vhd:179` time-multiplexes **one** RAM port between CPU and video:

```vhdl
ram_addr <= CPU_RAM_ADDR when PHASE_ZERO = '1' else "00" & VIDEO_ADDRESS;
```

and at `:200-213` the video side latches **main and aux in the same cycle**
(`VIDEO_DL_LATCH <= ram_do`), because 80-column text and DHGR need both bytes
simultaneously; `:214` then demuxes them at 7M.

Consequences:

- Aux bank 0 must stay low-latency and always available in parallel with main.
- Any CPU acceleration (turbo/TransWarp) needs its own RAM access slot or a second
  port — you cannot just clock the CPU faster.
- Any RamWorks expansion must keep bank 0 in block RAM for the video scanner and
  route only banks ≥1 elsewhere.

### Memory

`Apple-II.sv:406,416` — two inferred block RAM arrays:

- `ram0[196608]` = 192K: 64K main + 128K Saturn card RAM (`rtl/ramcard.v`)
- `ram1[65536]` = 64K aux

`ram_dout` is 16 bits, `{aux, main}`, read every cycle. **SDRAM and DDR3 are both
completely unused** (`Apple-II.sv:29-30` ties them off) — that is the headroom for
any future memory expansion.

### Resource budget (measured, Quartus 17.0.2, post No-Slot Clock)

```
ALMs           18,912 / 41,910   (45%)
Block memory    3,063,396 / 5,662,720 bits  (54%)
RAM Blocks        399 / 553      (72%)
DSP Blocks         43 / 112      (38%)
PLLs                3 / 6        (50%)
```

Timing is met with everything positive: worst-case setup slack 0.380 ns (in the HDMI
PLL domain, framework side; `clk_sys` itself has 5.523 ns), worst-case hold 0.250 ns,
TNS 0.000 on every domain.

Swapping the slot-1 clock card for `no_slot_clock.v` cost 155 ALMs and gave back
2,048 memory bits — the card's 256-byte ROM. RAM blocks did not move.

**Blocks bind before bits** (72% vs 54%) because the scaler's wide/shallow RAMs waste
M10K depth. Only ~154 blocks are free; one 64K RAM bank costs 64. Plan accordingly.

### Slots

Fixed unless noted:

| Slot | Card | Source |
|------|------|--------|
| 0 | Language card | `rtl/apple2.vhd` |
| 1 | *(empty)* | — |
| 2 | Super Serial Card | `rtl/ssc/` |
| 3 | 80-col + 64K aux (//e) | `rtl/apple2.vhd` |
| 4 | Mockingboard **or** mouse **or** empty | OSD-selected |
| 5 | Mouse **or** Mockingboard **or** 128K Saturn **or** empty | OSD-selected |
| 6 | Disk II | `rtl/disk_ii.vhd`, `drive_ii.vhd`, `floppy_track.sv` |
| 7 | HDD (ProDOS block device) | `rtl/hdd.vhd`, `hdd_rom.vhd` |

Slot muxing is by `IO_SELECT(n)` / `DEVICE_SELECT(n)` in `rtl/apple2_top.vhd:323-330`.

`rtl/no_slot_clock.v` (DS1216E) is deliberately **not** in that table. It takes no
slot and no address space: it snoops every peripheral ROM page and the `$C800`
window (`NSC_CS` in `apple2_top.vhd`) and stays silent until a driver shifts in the
64-bit `5CA33AC55CA33AC5` unlock pattern on A0. Time comes from the HPS `RTC` port,
with an on-chip BCD ticker advancing it between HPS updates. OSD bit `o1` disables
it. It replaced the old slot-1 clock card, which needed a slot and its own ROM.
`rtl/tb_no_slot_clock.v` is its unit test — the one iverilog testbench in the tree:

```bash
iverilog -g2005 -o /tmp/tb_nsc rtl/tb_no_slot_clock.v rtl/no_slot_clock.v && /tmp/tb_nsc
```

### Video

`rtl/video_generator.vhd` produces the Apple's 1-bit dot stream;
`rtl/vga_controller.vhd` does NTSC-to-RGB colour interpolation and line doubling.
The palette work added in `fb734d4` (gray-seam fix, NTSC vertical comb) lives in
`vga_controller.vhd`. Custom palettes load from a `.A2P` file via the OSD.

### Disk

- `rtl/floppy_track.sv` holds one 8 KB track buffer per drive, filled by the HPS
  with 13 × 512-byte LBAs at `lba = track * 13`.
- `rtl/drive_ii.vhd` serves **one byte every 64 CLK_2M ticks (32 µs)** from a fixed
  6656-byte track, wrapping at `X"19FF"`. Head position is `phase(7 downto 2)`, so
  35 whole tracks, **no quarter tracks, no bit-level timing, no WOZ**.
- Nibblization happens on the HPS side in `Main_MiSTer/support/a2/dsk2nib_lib.cpp`,
  not here.

See `TODO.md` — replacing this with the IIgs core's WOZ engine is the largest
planned item.

## Conventions and gotchas

Things that have bitten us. Check these before debugging something weird.

- **`LED_USER` is active high** ("1 - ON, 0 - OFF", `sys/emu_ports.vh:69`). Upstream
  `apple2_top.vhd` had `DISK_ACT <= not (...)`, which lit the LED when the disk was
  *idle*. Fixed here in `c65cfe0`.
- **OSD status bits are nearly exhausted.** `O0`–`OV` (bits 0–31) are fully used and
  bit 32 (`o0`) is taken by NTSC vertical blend and bit 33 (`o1`) by the No-Slot
  Clock enable. New options must use `o2` and up.
- **The CPU holds its address across internal cycles.** `R65Cx2.vhd`'s `calcAddr`
  ends with `when others => null` (`:1494`), so `myAddr` keeps its value on any
  cycle that does not compute a new address. One logical CPU access therefore
  leaves a slot's `IO_SELECT`/`IO_STROBE` asserted across **several**
  `PHASE_ZERO_R` pulses — measured at 5 for Applesoft's `LDA (zp),Y`. The 65C02
  is the default (`cpu_type = ~status[5]`, `status` defaults to 0).
  Stateless cards (ROM reads) don't care. **Any card that changes state per
  access must edge-qualify it** — take one event per contiguous run of chip
  select, or it will fire several times for a single access. This is what broke
  `no_slot_clock.v`: every pattern bit got shifted in five times and the 64-bit
  unlock could never align. Its testbench now models the hold explicitly.
- **A card's `OE` must be a level, not a `cycle_en` pulse.** `PD` in
  `apple2_top.vhd:319-326` is a combinational mux, and the CPU does not latch it
  until a clock *after* PHI0 falls (`CPU_EN`, `apple2.vhd:502`). `PHASE_ZERO_R`
  fires at the other end of the cycle — 14 clocks earlier — so an `OE` gated on it
  is long gone by the time the CPU reads. Latch the byte at `PHASE_ZERO_R` and hold
  both it and `OE` for the whole cycle. This bit `no_slot_clock.v` during
  development; its testbench now models a full 14-clock cycle and samples late so
  the mistake cannot come back.
- **The audio mix clamps at 1023.** Two Mockingboards peak at 765 each
  (`mockingboard.vhd:171`) plus 128 for the speaker = 1658, which does not fit in
  the 10-bit `AUDIO_L`/`AUDIO_R` ports. It used to wrap; `apple2_top.vhd` now sums
  in 12 bits and saturates. Gain is unchanged, so the common case (one board plus
  speaker, 893) sounds exactly as before. **Any new audio source eats the
  remaining headroom** - re-check the peak, and consider rescaling rather than
  piling more onto the clamp.
- **The speaker is box-averaged now, not point-sampled.** `$C030` toggles a
  flip-flop (`apple2.vhd:321-328`); it used to go straight into `audio(7)` and get
  sampled at 48 kHz, so anything driven fast aliased. Measured over HDMI capture:
  an 11-cycle toggle loop (46.4 kHz square) produced a **1614 Hz** tone —
  exactly `48000-46386`, present nowhere in the source. `rtl/speaker_filter.v` now
  averages over 256 `clk_sys` cycles, which measured −14.2 dB on that alias and
  −0.0 dB on a 1 kHz control. The framework's default IIR (`sys/sys_top.v:339-347`)
  does run before the 48 kHz decimation but is far too gentle to stop this.
- **`.po` and `.do` images are served raw.** `Main_MiSTer/user_io.cpp:2155` routes
  only `.dsk` to `SD_TYPE_A2` nibblization, though `CONF_STR` advertises
  `"S0,NIBDSKDO PO ;"`. `.nib` works only because raw passthrough happens to be the
  right layout.
- **`floppy_track.sv` does not clamp the track number.** `track` is 6 bits from
  `drive_ii.vhd:124` with no limit of 34, so tracks ≥35 read past the image.
- **Only `.nib` persists writes** to disk today.
- `CPU_WAIT` already exists and is wired (`apple2.vhd:517,536`), driven by the HDD
  (`Apple-II.sv:286`). Reuse it rather than inventing a second stall path.

## Testing

Verification today is:

1. **iverilog unit tests** for the Verilog modules — `rtl/tb_no_slot_clock.v` and
   `rtl/tb_speaker_filter.v`. Both model *this core's* bus and clock, not an
   idealised one; see the address-hold note above for why that distinction has
   already cost three bugs.
2. `quartus_map` + `quartus_fit` — catches resource and inference regressions early.
3. Full compile and run on hardware.

**The MiSTer can be driven entirely from here**, which makes hardware testing cheap:

- `load_core` / `screenshot` over `/dev/MiSTer_cmd` (`Main_MiSTer/input.cpp:6236`).
  Always check the screenshot filename advanced — a stale frame looks like a
  working test and has fooled us before.
- mrext's REST API on `:8182`: `POST /api/launch` with an absolute path mounts a
  disk *and* loads the matching core; `POST /api/controls/keyboard-raw/{code}`
  sends a keycode (press-and-release only, so no shifted characters).
- A uinput virtual keyboard on the MiSTer covers what the raw API cannot. Note the
  Apple II has a **single-character keyboard latch and no buffer**, so anything
  typed while Applesoft tokenises a line is silently dropped — allow ~0.9 s after
  every Enter, and MiSTer's inotify drops the first keystrokes after the device
  appears.
- **An HDMI capture dongle (MS2109, `hw:2,0`) gives 48 kHz stereo audio**, so audio
  changes can be measured rather than guessed at: drive a known waveform from a
  short ML loop, `arecord`, and compare spectra before and after.

When adding anything timing-sensitive, prefer to prototype it in the **Apple IIgs
core's Verilator harness** (`../Apple-IIgs_MiSTer/vsim/`), which has a real
`--woz`/`--floppy` path, screenshot capture, key injection, and a
`regression.sh`. That is where WOZ work should be simulated before it is ported
here. Its `vsim/disks_525/` holds ~2,860 5.25" WOZ images plus a batch test
harness (`vsim/test_woz_batch.sh`).

Standing goal: this core deserves an equivalent harness. Until it has one, be
conservative and test on hardware.
